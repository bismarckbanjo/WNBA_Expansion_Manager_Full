Executive view

Strong prototype, fragile state transitions

The visual system is cohesive and the game has more depth than its small footprint suggests. The main risk is not the simulation core; it is that one global state object, whole-page rendering, and lightly validated transitions allow a few actions to corrupt competitive or saved state.

10 suggestions

UI / UX

Prioritize responsive behavior, accessibility, and a clearer first-season decision flow.

High

Put the setup form before a full-screen promo on phones

The layout stacks below 1050 px, but the hero keeps its 670 px minimum height (styles.css:329–378, 684–732). On a phone, the actionable setup form therefore begins roughly a screen below the headline.

Reduce the hero to a compact 220–320 px introduction at the stacked breakpoint, or place the form first on narrow screens.

High

Do not hide cap data on mobile

At ≤700 px, every table’s fourth and fifth columns disappear globally (styles.css:721–726), including salary and contract details that drive roster decisions.

Use responsive roster cards or per-table rules so critical values remain available without horizontal guessing.

High

Create an opening-night readiness gate

The top bar exposes “Play Next Game” immediately after setup even with a 0-player roster, while the game defines an 11-player minimum (app.js:397–429; data.js:9–11).

Replace the play action with a checklist until roster count, position coverage, and cap requirements are satisfied.

Medium

Make mobile navigation compact and persistent

Nine destinations become a tall 2-column block and the sidebar loses sticky positioning below 1050 px (styles.css:684–732).

Use a sticky bottom bar for primary areas plus a “More” sheet for League, Coaching, and Admin.

High

Associate labels with every form control

Most labels have no for; filters rely on placeholders; several controls have no accessible name (app.js:585–599, 1777, 3393–3500).

Give controls stable IDs/names, connect labels, and use fieldsets/legends for grouped choices.

High

Give modals real dialog behavior

The scout and coach overlays are plain divs with no dialog role, focus trap, Escape handler, initial focus, or focus restoration (app.js:1801–1840).

Use <dialog> or implement role="dialog", aria-modal, labelled headings, trapping, Escape close, and return focus.

Medium

Make preset-city tiles keyboard operable

City tiles are clickable divs; only pointer handlers are attached (app.js:1777, 1923–1926). The duplicate select helps, but the richer tile UI remains inaccessible.

Render tiles as radio inputs or buttons with selected state and arrow-key navigation.

High

Protect contrast and focus across custom colors

White text is placed on a fixed orange and user-selected colors drive bars/badges without contrast validation (styles.css:121–130; app.js:365–380).

Calculate a readable foreground, constrain unsafe palettes, and add a consistent :focus-visible ring to every interactive control.

Medium

Explain simulation shorthand in place

Labels such as “Per O,” “Per D,” “Int O,” “Diff,” “MIP,” and “power index” appear without a glossary (app.js:1601–1680, 1724–1749).

Add plain-language tooltips and one reusable “How ratings work” panel, especially on Game Day.

Medium

Add transaction review and Undo

Draft and trade actions commit immediately; only a toast/log follows (app.js:2069–2144). A mis-click can permanently reshape the save.

Show a before/after confirmation for trades and offer one-step Undo for draft, waive, signing, and coach changes.

10 suggestions

Code hygiene

The code is readable within functions, but file size and shared mutable scope make changes increasingly risky.

High

Split the 3,605-line application by responsibility

app.js contains persistence, rendering, trades, simulation, playoffs, awards, coaching, and admin in one global scope.

Extract state.js, engine.js, actions.js, selectors.js, and focused view modules.

High

Make the simulation engine pure

Core functions read and mutate global S, global caches, and Math.random() (app.js:1062–1465).

Pass rosters, coaching modifiers, and an RNG explicitly; return events/state changes instead of mutating globals.

Medium

Separate literal data from factories

data.js is 5,399 lines but ends with runtime helpers and random mood generation (data.js:5345–5398).

Keep data deterministic and literal; move team, p, and slug to a factory/normalization module.

High

Replace full-page rendering with scoped updates

Every interaction rebuilds #app with innerHTML, then tries to reconstruct focus (app.js:338–380).

Render only the active surface, or adopt small view components with stable DOM identity.

Medium

Use delegated events instead of rebinding the page

bind() performs many querySelectorAll passes after every render (app.js:1842–1979).

Attach one click/input/change handler to the app root and route by data-* attributes.

Medium

Move inline presentation into CSS components

Views contain extensive repeated style="…" strings for spacing, flex layouts, colors, and emphasis throughout app.js.

Create semantic component and utility classes; this also makes responsive and high-contrast changes safer.

Medium

Centralize balance rules and domain constants

Rating weights, home advantage, injury odds, trade thresholds, development gains, and rotation weights are embedded across functions.

Create a versioned BALANCE configuration with units and comments, then snapshot it in saves.

High

Adopt a formal state schema

Migration and validation are hand-written and validate only a few top-level properties (app.js:101–175).

Define a schema with defaults, enums, ranges, and nested collection checks; validate both load and import.

Medium

Add formatting, linting, and lightweight types

package.json exposes only npm test; there is no automated static analysis.

Add Prettier, ESLint, and either TypeScript or // @ts-check with JSDoc domain types.

Medium

Remove or finish dead and debug-only state

reports, currentGameIndex, and weeklyFocusWeek are written but not meaningfully read; window.simTest ships globally (app.js:98, 979, 1272, 3071).

Delete unused fields or implement them, and move diagnostics behind a development-only module.

10 confirmed fixes

Bug fixes

These are reproducible defects or direct state-integrity failures, not speculative feature requests.

Critical

Stop the same base free agent being signed repeatedly

waiverPool() always re-adds cached base free agents, while signPlayer() never removes them (app.js:821–931, 2101–2110). A targeted DOM probe signed morgan-tuck-fa twice and produced two roster rows with the same ID.

Track base-FA availability by ID and reject any player already present on a roster.

Critical

Prevent draft-pick inventories from going negative

Trade submission decrements S.picks.you or S.picks.league without checking availability (app.js:2112–2134).

Disable unavailable pick controls and enforce non-negative inventory inside the transaction function.

High

Enforce roster limits during the rookie draft

userPickRookie() pushes directly to S.roster without the rosterMax check used by signings (app.js:2533–2556).

Require a roster slot or a corresponding waive/release step before confirming the pick.

High

Apply “weekly” effects once per week, not once per user game

applyWeeklyTransition() runs after every user game, even though the UI promises “+1 rating per week”; generated weeks can contain multiple user games (app.js:1408–1431, 3102–3135). weeklyFocusWeek is recorded but never used.

Advance weekly effects only when the calendar crosses into a new week.

High

Do not immediately consume a new injury’s first missed game

A game rolls injuries and then decrements all injuries in the same transition (app.js:1383, 1430, 3137–3181). A 1-game injury can clear immediately and miss no future game.

Tick existing injuries before the game or stamp injuries with the game/week they began.

High

Invalidate composite caches inside offseason aging

ageOnePlayer() calls cached composite(), mutates ratings, then calls it again without invalidation (app.js:2184–2220). A probe changed scoring by +10 and observed cached 79 versus fresh 81.

Clear the player’s cached value after mutations or make composite calculation pure and uncached in reports.

Medium

Show the user’s next game in the “Next Game” KPI

seasonKpis() calls nextUnplayed(), which returns the next league game, not the next user game (app.js:1467–1476, 1724–1735).

Use nextUserGame() so the label and matchup match the user-facing promise.

High

Reject malformed nested saves before assignment

isValidSave() accepts any object with a team city and two arrays; a probe confirmed that {started:true, team:{city:"X"}, roster:[], teams:[]} passes (app.js:158–175). Rendering then expects objectives, colors, coaches, and valid team/player records.

Validate and normalize the full state into a temporary object, render-test it, then atomically replace S.

High

Escape all user text used inside HTML attributes

Nickname, arena, draft query, and trade query values are inserted raw into quoted attributes (app.js:585–599, 683–700, 1777). Angle-bracket escaping elsewhere does not protect these contexts.

Use a dedicated attribute escaper or set control values via DOM properties after creating the markup; add reload/import injection tests.

Medium

Resolve expired contracts instead of carrying 0-year players forever

Offseason aging decrements contract years to zero, but no free-agency/re-sign/release transition follows (app.js:2184–2232). Their salary remains in payroll calculations.

Move expiring players into a free-agent decision flow before generating the next season.

10 suggestions

Miscellaneous

Product depth, competitive integrity, data stewardship, delivery, and long-term replay value.

High

Make the regular-season schedule competitively even

Double round-robin creates 30 games per team, then eight user showcase games are added (app.js:1024–1060). A probe found team totals ranging from 30 to 38 games.

Use one target game count for every team and rotate showcase labels onto existing matchups.

Medium

Turn awards into durable history

Awards are accumulated in S.awards but never displayed; MIP can select the least-negative player and render a “+-N” change (app.js:2930–3021).

Store immutable award snapshots, require positive improvement for MIP, and add a franchise-history screen.

High

Complete the contract and free-agency loop

Contract years exist and age, but there are no offers, extensions, bird rights, releases, or CPU free-agent moves.

Add an offseason contract stage with clear cap consequences and AI bidding.

Medium

Support multiple named save slots

One localStorage key holds the entire game (app.js:2, 169–208); starting over replaces it.

Add named franchises, autosave timestamps, export/import preview, and a recoverable backup slot.

Medium

Add seeded seasons and replayable outcomes

Gameplay uses global Math.random() across data creation, simulation, injuries, development, and drafts.

Persist an RNG seed and event index so bugs can be reproduced and players can share challenges.

Medium

Make portraits resilient and offline-friendly

Player headshots load at runtime from ESPN; failures silently hide the image (app.js:300–313).

Confirm usage rights, cache or bundle approved assets, and retain a designed initials fallback for offline play.

Medium

Document roster-data provenance and refresh dates

The README calls the roster scaffold publicly grounded, while data.js contains thousands of manually embedded facts and abstractions without per-source dates.

Add a data manifest listing source, retrieval date, license/permission, fictional fields, and update owner.

Medium

Build a repeatable balance laboratory

window.simTest can run seasons but has no assertions, baselines, distribution report, or regression threshold (app.js:1272–1307).

Run thousands of seeded seasons and report win-rate spread, home advantage, scoring, injuries, and roster-strength correlation.

High

Add continuous integration and browser quality gates

Tests run locally, but no checked-in CI, lint, accessibility, or responsive browser checks are present.

On every change, run unit/integration tests, formatting, schema fixtures, axe, and desktop/mobile screenshots.

Medium

Define deployment security and failure behavior

The app relies on inline HTML templates, external images, localStorage, and console-only errors, with no documented CSP or user-visible recovery path.

Set a realistic Content Security Policy, catch storage failures, show recovery guidance, and keep any diagnostics privacy-preserving and opt-in.
